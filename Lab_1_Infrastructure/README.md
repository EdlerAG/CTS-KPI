# Лабораторна 1 (Мілстоун 1): Інфраструктура

**Мета:** підняти хмарний акаунт і базову мережу (VPC), у якій житиме проєкт, та налаштувати безпечний доступ без використання `root`.

**Максимум балів:** 15 (Базовий рівень — 10, Розширений — до 5).

---

## Що потрібно для виконання (Інструменти та пререквізити)
1. **Хмарний акаунт:** AWS (Free Tier / кредити) або GCP (\$300 стартових кредитів). Якщо немає платіжної картки — звернутися до викладача за IAM-користувачем.
2. **Одразу після реєстрації:** налаштувати **Budget Alert / Billing Alarm** (наприклад, на \$1–\$5), щоб не пропустити випадкові витрати.
3. **CLI та клієнти:**
   - AWS CLI v2 (`aws`) або Google Cloud CLI (`gcloud`).
   - Для розширеного рівня (IaC): **Terraform / OpenTofu** або **AWS CloudFormation** / CDK.
4. **Артефакти для захисту:**
   - Робочий акаунт у хмарі (жива демонстрація в консолі або через CLI).
   - Файл/розрахунок місячного бюджету для Мілстоуна 2 (2 шарди + координатор).
   - (За вибором) IaC-шаблони (`.tf` або `.yaml`) у цій папці.

---

## Базовий рівень (10 балів)
- [x] **Admin IAM-користувач (2 бали):** Зареєструвати акаунт у хмарного провайдера. Створити IAM-користувача з правами адміністратора (і MFA) та надалі працювати лише під ним (під `root` не працювати). (`admin-edler`)
- [x] **Read-Only користувач і політика (2 бали):** Створити другого користувача та політику, яка дозволяє **ЛИШЕ** переглядати ресурси без права запису/зміни. (`kv-readonly-user` + `kpi-kv-store-readonly-policy`)
- [x] **IAM-роль (2 бали):** Створити роль із привʼязаною read-only політикою, яку може прийняти (`AssumeRole`) користувач із п. 2. (`kpi-kv-store-readonly-role`)
- [x] **Мережа VPC (3 бали):** Створити VPC з **публічною** та **приватною** підмережами. Публічна має маршрут через Internet Gateway (`0.0.0.0/0 -> IGW`), приватна — лише для внутрішнього доступу (без прямого доступу з інтернету). (`vpc-08deb24703402b608`)
- [x] **Бюджет для Мілстоуна 2 (1 бал):** Порахувати очікуваний місячний бюджет для Мілстоуна 2 за умови, що буде 2 шарди (+ координатор, трафік, диски тощо). (`budget_milestone2.md`)

## Розширений рівень (до 5 балів)
- [x] **IAM Identity Center (1 бал):** Використати IAM Identity Center (AWS SSO) замість звичайного IAM-користувача. (`ssoins-650893b8f2a27357`)
- [x] **Organisation (1 бал):** Створити Organization і виконувати всі подальші роботи всередині неї. (`o-pgdvxqzrq1`)
- [x] **IaC для IAM (1 бал):** Описати read-only політику та роль у вигляді IaC-шаблону (Terraform / OpenTofu / CloudFormation). (`terraform/iam.tf`)
- [x] **IaC для мережі (2 бали):** Описати VPC, підмережі, маршрути та IGW у вигляді IaC-стека. (`terraform/vpc.tf`)

## Контрольні питання до захисту
1. `*aaS` (IaaS, PaaS, SaaS, FaaS). Порівняйте хмарні моделі. Коли яку використовувати?
2. Регіони, зони доступності (AZ) — що це і навіщо?
3. Що таке IaC і в чому його цінність?
4. Різниця між ролями (Roles) та групами користувачів (User Groups) при призначенні політик.
5. VPC: CIDR, розрахунок блоків адрес (скільки IP у `/16`, `/24`, зарезервовані адреси хмари).
6. Як влаштовані публічна та приватна підмережі? Що куди маршрутизується (Route Tables, IGW, NAT)?
7. Коли використовувати `Allow`-, а коли `Deny`-політики (explicit deny vs implicit deny)?
